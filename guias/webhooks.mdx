A SkalePayments envia requisições HTTP `POST` com JSON quando o status de uma transação muda.

## Formas de receber eventos

<AccordionGroup>
  <Accordion title="Postback da transação" icon="link">
    Informe `postbackUrl` ao criar a transação. Essa URL recebe todos os status da transação, independentemente das configurações do painel.
  </Accordion>
  <Accordion title="Webhooks cadastrados no painel" icon="settings">
    Cadastre URLs no painel, escolha os eventos recebidos e, quando necessário, configure `application-id` e `webhook-secret`.
  </Accordion>
</AccordionGroup>

## Requisitos do endpoint

- Utilize uma URL HTTPS pública.
- Aceite requisições `POST` com `Content-Type: application/json`.
- Responda em até 10 segundos.
- Retorne HTTP `2xx` depois de persistir o evento.
- Processe eventos de forma idempotente.

Em falhas de rede, respostas `5xx` ou `429`, a entrega é repetida automaticamente com backoff. Seu endpoint deve aceitar eventos duplicados com segurança.

## Headers enviados

| Header | Quando é enviado |
| --- | --- |
| `Content-Type: application/json` | Sempre |
| `application-id` | Webhook do painel configurado com essa credencial |
| `webhook-secret` | Webhook do painel configurado com esse segredo |

<Note>
  O `postbackUrl` informado diretamente na transação não envia `application-id` nem `webhook-secret`.
</Note>


## Campos principais

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `id` | string | Identificador retornado na criação |
| `status` | string | Estado atual da transação |
| `end2EndId` | string ou null | Identificador fim a fim do PIX |
| `pix` | object ou null | Dados do QR Code, comprovante e expiração |
| `metadata` | object | Metadados enviados na criação |
| `postbackUrl` | string ou null | URL de postback associada à transação |
| `user` | object | Dados do pagador |
| `address` | object ou null | Endereço, quando informado |
| `transaction` | object | Dados financeiros e de conciliação |

## Resposta recomendada

```http
HTTP/1.1 204 No Content
```

Responda somente depois que o evento estiver salvo. Execute tarefas demoradas de maneira assíncrona.
